# SEO Research

Create an observation-backed SEO brief for a specific query, locale, device context, and date.

## Establish the brief

1. Confirm the target market and language, audience, offer, page type, primary conversion, and existing URL if any.
2. Define the primary query and the decision: create, refresh, consolidate, redirect, or leave unchanged.
3. Read [`references/live-serp-protocol.md`](references/live-serp-protocol.md) before collecting search observations.

## Choose the operating mode

- **Live retrieval available:** Observe the current result page and candidate competitor pages. Record date, market, and tool limitations.
- **User-supplied export:** Analyze only the supplied Search Console, keyword-tool, or SERP data and state its date range.
- **No current evidence:** Produce a research plan, not an SEO brief. Label all keyword ideas as hypotheses and do not report ranking, volume, or difficulty.

## Research workflow

1. Classify dominant and secondary intent from result types, not from the query wording alone.
2. Record result features, page formats, freshness patterns, recurring entities, questions, and evidence expectations.
3. Inspect relevant competing pages for coverage, structure, proof, differentiation, and unresolved user needs.
4. Map query and topic clusters without treating every wording variant as a separate page.
5. Check whether an existing page already satisfies the intent before recommending a new one.
6. Copy [`assets/seo-research-brief.md`](assets/seo-research-brief.md) and separate measured data from qualitative observations.

## Completion checks

- Never guarantee rankings, clicks, traffic, or conversions.
- Do not invent search volume, keyword difficulty, position, or SERP features.
- Preserve the observation date and target market for volatile findings.
- Recommend content that satisfies intent rather than keyword stuffing.
- Identify which claims require first-party product evidence or expert review.
